NULLを含み得るサブクエリにNOT INを使う

顧客一覧から、まだ注文していない人を探します。customersは顧客、ordersは注文です。orders.customer_idは注文した顧客のidで、NULLは顧客が未確定の注文を表します。

入力表

入力：customers（顧客）
idname
1Aki
2Beni
3Chika
入力：orders（注文）
idcustomer_id
1011
102NULL

目的と期待結果

注文と対応しない顧客だけを、id順に取り出します。Akiには注文101があるため除き、BeniとChikaを残したい場面です。

期待結果／改善SQLの結果
idname
2Beni
3Chika

必要な仕組み

NOT INは候補の値すべてとの比較を否定します。候補にNULLが混ざると、1と一致しない2や3でも結果は不明となり、WHEREを通りません。NOT EXISTSは顧客ごとに一致する注文が存在するかを調べるため、顧客未確定の注文に影響されません。

問い

この入力表でNOT INを使うと、BeniとChikaを残せるでしょうか。NULLの注文102を除いた場合とも比べてください。

問題SQL

SELECT id, name FROM customers WHERE id NOT IN (SELECT customer_id FROM orders) ORDER BY id;
問題SQLの結果（0行）
idname
0行（該当なし）

予想と理由

元fixtureの未注文顧客は2と3です。NULLを含むNOT INは0行、NOT EXISTSは2と3を返します。NULL行を除くと両方2と3、注文を空にすると両方1・2・3です。

改善SQL

SELECT c.id, c.name FROM customers AS c WHERE NOT EXISTS (SELECT 1 FROM orders AS o WHERE o.customer_id = c.id) ORDER BY c.id;

改善SQLの結果は上の「期待結果」の表と一致します。

条件と限界

左辺idは非NULLの主キーです。左辺もNULLを取り得る場合まで同じ説明を一般化しません。

次に確かめること

「未登録を探す」SQLでは、右側のNULL可否と空集合を先に確認してください。次の009では、集計する一件の意味を確認します。
