インデックス列を式で包んで検索する

paymentsは支払い一覧です。amount_centsは整数のセント単位で、100セントが1単位です。この列には通常のインデックスidx_payments_amountがあります。

目的と期待結果

50単位以上51単位未満、つまり5000以上5100未満の支払いidを取り出します。境界4999と5100を除き、5000・5050・5099のid=2,3,4を残します。

必要な仕組み

この正の整数fixtureではamount_cents / 100が整数除算となり、5000〜5099は50です。ただし列を式で包む条件は、この通常インデックスによる範囲探索になりません。列自体を5000以上5100未満と比較すると、同じ結果を範囲探索で探せます。

問い

両方のSQLでid=2,3,4が返っても、何を追加で確認すれば探索方法の違いが分かるでしょうか。

問題SQL

SELECT id FROM payments WHERE amount_cents / 100 = 50 ORDER BY id;
問題SQLの結果（結果は同じ）
id
2
3
4

予想と理由

5000以上5100未満が対象で、fixtureのidは2・3・4です。式の条件と範囲条件の結果は同じですが、固定fixtureでは前者SCAN、後者は名前付きindexのSEARCHを確認します。

改善SQL

SELECT id FROM payments WHERE amount_cents >= 5000 AND amount_cents < 5100 ORDER BY id;

改善SQLの結果は上の「期待結果」の表と一致します。

条件と限界

query planは実測速度ではありません。速度倍率や別SQLite版での同一planを保証しません。負数や別の丸め規則には別の境界定義が必要です。

次に確かめること

EXPLAIN QUERY PLANのSCANとSEARCH、使用indexと範囲条件を確認します。この固定fixtureでは問題側SCAN、改善側SEARCHですが、速度の倍率や他環境での計画は保証しません。
